Core Skill Area: Enterprise Networking & Perimeter Defense

Networking encompasses the architectural design, physical and logical construction, and operational governance of telecommunication protocols and routing hardware used to transport data securely across local and wide area networks (Rouse, n.d.).

For a Systems and Security Administrator, networking is the foundational layer: you cannot secure traffic that you cannot route, segment, or inspect. Mastering dynamic routing (OSPF), VLAN segmentation, and packet filtering (ACLs) directly bridges infrastructure reliability with zero-trust security.

Problem & Context (Course Assignment)

Enterprise Multi-VLAN OSPF & ACL Implementation

In our NSCC networking coursework, we were tasked with designing and configuring an enterprise branch network in Cisco Packet Tracer to meet strict organizational and security requirements:

  • Departmental Segmentation: Separate network traffic across four distinct departments (Engineering, HR/Finance, Guest Wi-Fi, and IT Management VLAN 99) so broadcast domains remain isolated.
  • Dynamic Routing: Configure single-area and multi-area OSPF (Open Shortest Path First) across core and distribution routers to ensure redundant, self-healing paths without relying on static routes.
  • Address Conservation: Calculate and apply VLSM (Variable Length Subnet Masking) across the 172.16.0.0/16 space so subnets match actual host requirements rather than wasting entire Class C blocks.
  • Policy Enforcement: Implement Standard and Extended Access Control Lists (ACLs) using precise wildcard masks to restrict SSH management access exclusively to the IT Management subnet and block Guest VLAN traffic from reaching internal servers.

Cisco IOS Configuration Excerpt

Below is the actual configuration applied to the Core Router (R1-Core) to establish 802.1Q trunking, OSPF routing with passive interfaces, and Extended ACL perimeter filtering: 

! 1. Configure 802.1Q Sub-interfaces for Inter-VLAN Routing
interface GigabitEthernet0/0/0.10
 description Engineering_VLAN
 encapsulation dot1Q 10
 ip address 172.16.10.1 255.255.255.192
 ip access-group RESTRICT-GUEST in
!
interface GigabitEthernet0/0/0.99
 description IT_Management_VLAN
 encapsulation dot1Q 99
 ip address 172.16.99.1 255.255.255.240
!
! 2. Configure OSPF Process 10 with Exact Wildcard Masks
router ospf 10
 router-id 1.1.1.1
 passive-interface default
 no passive-interface GigabitEthernet0/0/1
 network 172.16.10.0 0.0.0.63 area 0
 network 172.16.10.64 0.0.0.31 area 0
 network 172.16.99.0 0.0.0.15 area 0
 network 172.16.254.0 0.0.0.3 area 0
!
! 3. Extended ACL: Block Guest VLAN from HR/Finance & Mgmt, Allow Internet
ip access-list extended RESTRICT-GUEST
 remark Deny Guest (VLAN 30) access to HR/Finance (VLAN 20)
 deny ip 172.16.10.96 0.0.0.31 172.16.10.64 0.0.0.31 log
 remark Deny Guest access to IT Management Subnet (VLAN 99)
 deny ip 172.16.10.96 0.0.0.31 172.16.99.0 0.0.0.15 log
 remark Permit all other valid outbound traffic
 permit ip any any
!
! 4. Harden VTY Lines for SSH-Only Access from VLAN 99
ip access-list standard VTY-SSH-ONLY
 permit 172.16.99.0 0.0.0.15
 deny any log
!
line vty 0 4
 access-class VTY-SSH-ONLY in
 transport input ssh
 login local

04. Breakthrough Moment & Critical Analysis

Evaluating the "Aha!" learning moment and analyzing why specific design decisions were made.

Significant Learning Moment ("Aha!" Breakthrough)

Directional ACL Logic & Wildcard Bitmask Inversion

My biggest breakthrough happened when troubleshooting why my Extended ACL initially broke OSPF neighbor adjacencies and blocked legitimate return web traffic. Initially, I applied the ACL outbound on the trunk interface without accounting for how stateless packet filters evaluate source/destination pairs.

The "aha!" moment clicked when I visualized the router's internal packet-processing pipeline: Extended ACLs must be placed as close to the source as possible (inbound on the specific sub-interface), whereas Standard ACLs belong closest to the destination. Furthermore, calculating inverse wildcard masks (subtracting the subnet mask from 255.255.255.255) transformed from a memorized math formula into a binary pattern-matching tool that gave me surgical control over which host bits the router inspected.

Analysis: Why Did I Do It This Way?

Engineering Decisions & Retrospective Improvements

  • Why `passive-interface default` in OSPF? By default, Cisco routers send OSPF Hello packets out of every OSPF-enabled interface. If an attacker plugs into an access port on VLAN 10, they could form a rogue OSPF adjacency and inject malicious routes. Setting `passive-interface default` and only enabling OSPF on core router-to-router links eliminates this attack vector.
  • Why SSH + `access-class` over Telnet? Even though legacy lab specs often ask for Telnet, Telnet transmits credentials in cleartext. I enforced `transport input ssh` alongside a VTY `access-class` tied to `172.16.99.0/28` so that even if an employee's workstation on VLAN 10 is compromised, the router drops any SSH connection attempt at the network layer.
  • Progression of Learning (How I Would Improve It Further): In the example work sample, a flat `/24` was used across all VLANs. By implementing VLSM (`/26`, `/27`, `/28`), I already reduced unused IP exposure by over 75%. Looking ahead, I would further harden this topology by enabling DHCP Snooping and Dynamic ARP Inspection (DAI) on the access switches to prevent ARP spoofing within each VLAN.

05. Business Benefit & Portfolio Ecosystem

Translating technical configurations into measurable organizational value.

1. Blast-Radius Containment

By isolating Guest Wi-Fi, HR/Finance, and Engineering into separate VLANs filtered by Extended ACLs, a malware infection or unauthorized device on the Guest network cannot laterally move into sensitive financial databases or management planes.

2. High Availability & Scalability

Replacing static routes with OSPF and LACP EtherChannel trunks means the business experiences automatic failover in milliseconds if a physical cable fails, minimizing costly downtime while conserving IPv4 address space via VLSM.

3. Regulatory & Audit Compliance

Restricting administrative VTY access to an encrypted protocol (SSH) from a dedicated management subnet (`172.16.99.0/28`) with ACL logging (`log`) directly satisfies principle-of-least-privilege requirements in enterprise security audits.
