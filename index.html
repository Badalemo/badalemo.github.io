Self-Healing Routing & 78% IPv4 Conservation

Problem Context: Static routing fails to scale as branch routers are added, and assigning default Class C /24 masks (254 usable hosts) to a 10-host IT Management subnet or a 2-host WAN link wastes hundreds of IPv4 addresses.

Engineering Action: Calculated a Variable Length Subnet Mask (VLSM) schedule (/26, /27, /28, /30) and deployed OSPFv2 Process 10 (Area 0) using exact inverse wildcard masks and passive-interface default so OSPF Hello packets cannot be spoofed from employee or guest access ports.

PHASE 03 // ZERO-TRUST PERIMETER ACLS

Stateless Extended ACLs & SSHv2 VTY Locking

Engineering Action: Authored inbound Extended ACL RESTRICT-GUEST on Gi0/0/0.30 to drop traffic destined for HR/Finance and IT Management while permitting internet traffic, and locked VTY lines with transport input ssh and access-class VTY-ADMIN-ONLY in restricted to 172.16.99.0/28.

VULNERABILITY RESEARCH ARTIFACT

Cisco Catalyst SD-WAN Manager API (`CVE-2026-76504`)

In my cybersecurity coursework at NSCC, I investigated CVE-2026-76504 affecting the Cisco Catalyst SD-WAN Manager (formerly vManage) API. Because SD-WAN Manager acts as the centralized orchestration plane for an entire enterprise WAN fabric, an API authentication or request-validation flaw allows an attacker to read or manipulate overlay routing policies across all branch edges.

  • Attack Vector Analysis: Improper input/authentication validation on exposed REST API endpoints in Cisco Catalyst SD-WAN Manager allows crafted HTTPS requests to bypass standard RBAC checks.
  • Connection to My Work Sample: Even when zero-day vulnerabilities exist in vendor web APIs, enforcing strict network-layer segmentation—such as isolating management interfaces onto VLAN 99 (`172.16.99.0/28`) behind an inbound Extended ACL—prevents untrusted users on Guest or standard data VLANs from ever reaching the vulnerable SD-WAN Manager API port in the first place.

WORKSHEET ITEM 05 // SIGNIFICANT LEARNING MOMENT THE "AHA!" MOMENT

Visualizing Stateless ACL Directionality & Bitwise Wildcard Inversion

My most significant learning breakthrough occurred when troubleshooting why my initial Extended ACL broke OSPF neighbor adjacencies and dropped legitimate return web traffic. Coming from full-stack web development (where cloud security groups are stateful), I initially applied my Cisco ACL outbound on the wrong sub-interface without accounting for stateless packet evaluation.

The "Aha!" moment clicked when I traced the packet's exact lifecycle inside the router: Extended ACLs must be placed as close to the source as possible (`ip access-group RESTRICT-GUEST in` on `Gi0/0/0.30`) so unauthorized packets are dropped at ingress before the router wastes CPU cycles performing an OSPF routing table lookup. Simultaneously, calculating wildcard masks transformed from rote subtraction (`255.255.255.255 - Subnet Mask`) into a binary bitmask filter (`0` = must match, `1` = don't care) that I could also apply to SSH `AllowUsers` rules and firewall policies on my Linux servers.

WORKSHEET ITEM 06 // ANALYSIS OF WHAT I DID WHY THIS DESIGN?

Why I Engineered It This Way & Future Hardening

  • Why `passive-interface default` in OSPF? Without passive interfaces, the router broadcasts OSPF Hello multicast packets (`224.0.0.5`) onto every access VLAN, allowing an attacker with a packet crafting tool to form a rogue OSPF adjacency and poison the routing table.
  • Why SSHv2 + VTY `access-class` over Telnet? Legacy lab specs often use Telnet, which transmits administrative credentials in cleartext. Enforcing `transport input ssh` alongside a VTY ACL restricted to `172.16.99.0/28` ensures encrypted management only from authorized IT admin terminals—mirroring how I lock down SSH access on `afacs.org`.
  • How I Would Improve It Further: Looking back, while stateless Extended ACLs block inter-VLAN initiation, I would upgrade the router perimeter to a Zone-Based Policy Firewall (ZBPF) for stateful session inspection and enable DHCP Snooping + Dynamic ARP Inspection (DAI) on the switches.
BUSINESS BENEFIT 01 // CONTAINMENT
