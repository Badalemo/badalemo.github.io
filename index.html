PHASE 01 // THE CHALLENGE

Eliminating Flat Broadcast Domains

An expanding organization required network connectivity for a multi-department facility across the 172.16.0.0/16 private address space. Connecting Engineering workstations, HR/Finance records, Guest Wi-Fi users, and network management interfaces onto a flat switch fabric would expose sensitive financial traffic to packet sniffing and broadcast storms.

Requirement: Architect four isolated VLANs (VLAN 10, 20, 30, and Management VLAN 99) trunked across distribution switches using LACP EtherChannel for link aggregation.

PHASE 02 // DYNAMIC ROUTING

Self-Healing OSPF & VLSM Conservation

Static routing does not scale when new branch links are introduced, and allocating standard /24 subnets (254 hosts) to a 10-host Management VLAN or a 2-host point-to-point router link wastes hundreds of IPv4 addresses.

Requirement: Design a Variable Length Subnet Mask (VLSM) hierarchy and advertise routes dynamically using OSPF Process 10 (Area 0) with exact inverse wildcard masks and passive-interface hardening.

PHASE 03 // ZERO-TRUST PERIMETER

Surgical Extended ACL Enforcement

Once Inter-VLAN routing (Router-on-a-Stick) is active on R1-Core, all VLANs can route to one another by default. This creates a severe security vulnerability: a user on Guest Wi-Fi (VLAN 30) could probe HR servers (VLAN 20) or attempt brute-force logins against router VTY lines.

Requirement: Author inbound Extended Access Control Lists (ACLs) to block VLAN 30 from reaching VLAN 20 and VLAN 99 while permitting outbound internet traffic, and lock VTY lines exclusively to SSH connections originating from 172.16.99.0/28.

04 // SIGNIFICANT LEARNING MOMENT & ENGINEERING ANALYSIS

THE "AHA!" BREAKTHROUGH.

BREAKTHROUGH MOMENT PACKET PIPELINE

Visualizing Stateless ACL Directionality & Bitwise Inversion

My most significant learning breakthrough occurred when debugging why my initial Extended ACL broke OSPF neighbor adjacencies and dropped return HTTP traffic. At first, I treated ACLs like a stateful application firewall and applied the list outbound on the wrong sub-interface.

The "Aha!" moment clicked when I traced the packet's exact lifecycle inside the router: Extended ACLs must be placed as close to the source as possible (`ip access-group RESTRICT-GUEST in` on `Gi0/0/0.30`) so unauthorized packets are dropped before the router wastes CPU cycles performing a routing table lookup. Simultaneously, calculating wildcard masks shifted from rote subtraction (`255.255.255.255 - Subnet Mask`) to understanding binary `0` ("must match") and `1` ("don't care") bitmasks.

CRITICAL ANALYSIS WHY THIS DESIGN?

Why I Engineered It This Way (And Future Hardening)

  • Why `passive-interface default` in OSPF? Without passive interfaces, the router broadcasts OSPF Hello multicast packets (`224.0.0.5`) onto every access VLAN, allowing an attacker with a packet crafting tool to form a rogue OSPF adjacency and poison the routing table.
  • Why SSH + VTY `access-class` over Telnet? Legacy specifications often mention Telnet, which sends administrative credentials in cleartext. Enforcing `transport input ssh` alongside a VTY ACL restricted to `172.16.99.0/28` ensures encrypted management only from authorized admin hosts.
  • How I Would Improve It Further: Looking back, while stateless Extended ACLs block inter-VLAN initiation, I would upgrade the perimeter to a Zone-Based Policy Firewall (ZBPF) for stateful session inspection and enable DHCP Snooping + Dynamic ARP Inspection (DAI) on the switches.
